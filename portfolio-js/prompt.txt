# Portfolio UI Upgrade — Master Prompt

Paste this into Cursor / Lovable / v0 / Bolt. Execute phase by phase, reviewing the diff after each phase before moving to the next.

---

## Context (paste this first, always)

You are upgrading an existing developer portfolio site. The current aesthetic direction is correct and must be PRESERVED, not replaced:

- Palette: warm ivory background (#F4EFE8-ish), espresso/near-black text (#1C1410-ish), copper/terracotta accent (#B5652E-ish)
- Typography: Cormorant Garamond (or similar high-contrast serif) for display headings, italic used for emphasis words, a clean sans-serif (Inter or similar) for body/UI text
- Tone: editorial, restrained, premium — NOT a generic SaaS/AI-generated template with gradients, neon, or heavy shadows

The goal of this pass is **reduction and precision**, not redecoration. Every phase below is about removing clutter, fixing overlap bugs, and tightening spacing/hierarchy — not changing the color palette or fonts. Do not introduce new colors, new fonts, or a different layout system unless a phase explicitly says so.

Global rules for every phase:
- Use a strict 8px spacing scale (8/16/24/32/48/64/96) for all margins and padding — no arbitrary values.
- Every section needs consistent vertical rhythm: same top/bottom padding across sections unless there's a clear reason to break it.
- No element may visually overlap another unless it's an intentional, tested layered composition (e.g. a badge deliberately breaking a card edge by a few px). Accidental overlap = bug, fix it.
- Floating UI (chat widgets, buttons) must never sit on top of readable content at any scroll position or breakpoint — verify at 1440px, 1024px, 768px, and 375px.
- Test every text string against real content lengths, not lorem ipsum, so nothing truncates awkwardly.

## Phase 1 — Fix bugs (do this first, nothing else)

1. Find where hero copy renders `**AI automation**` literally with asterisks — this means markdown/rich-text isn't being parsed. Fix the rendering so it shows as proper bold text, or hardcode a `<strong>` tag if the content is static.
2. In the Skills & Stack section, find and remove the stray circular element overlapping the "Redis" list item.
3. Audit every bullet/list item across the Skills section — every item should have exactly one bullet marker, consistently styled (same size, same color, same offset). Fix any doubled markers.
4. In the Work History timeline, fix the duplicated year label per entry (currently showing the year twice with a broken arrow glyph between them). Each entry should show the year exactly once.
5. Fix the Work History description text getting clipped at the card boundary — the container must grow to fit content, not clip it.
6. Fix the floating WhatsApp/chat icon(s) so they never overlap page content — pin them with sufficient margin from the viewport edge, and confirm no card, button, or text sits underneath them at any scroll position across breakpoints.

Stop after this phase and show me the diff before continuing.

## Phase 2 — Hero section cleanup

1. Remove the top scrolling marquee ticker entirely, OR move it to a single thin static line (no animation, no duplicate nav-like content) directly above the main nav — pick whichever you think reads cleaner, but it cannot compete with the nav bar.
2. On the hero portrait image, reduce the overlay to ONE layer of information, not three. Recommended: keep just the name + role caption at the bottom (small, understated), and REMOVE the separate row of 6 tech pills sitting under the photo — that data is already covered in the Skills section further down the page.
3. Tighten the hero body paragraph to 2-3 short sentences max, one clear idea per sentence. Cut anything that repeats what's already said elsewhere (e.g. don't restate every technology — that's what the Skills section is for).
4. Keep exactly two CTAs (View Work / Download CV) but make sure their visual weight is intentional: one solid/filled primary, one ghost/text secondary — no more than that hierarchy.

## Phase 3 — Skills & Stack section

1. Standardize all skill cards to equal height using a grid with `align-items: stretch`, regardless of how many items are in each category — no more visible dead space.
2. If a category (e.g. Backend) has noticeably fewer items than others, either rebalance the categories or accept the shorter card height and let the grid reflow naturally (masonry-style) rather than forcing padding to fill it.
3. Keep the numbered badge (e.g. "09", "05") but make sure it's vertically aligned with the category label baseline.

---

## Phase 4 — Featured Projects section

1. Keep the browser-chrome card treatment (traffic light dots + path label) — it's a nice detail, keep it consistent across every card (same dot size, same path format).
2. Fix truncated project descriptions: set a fixed line-clamp (e.g. `-webkit-line-clamp: 2`) so every description card truncates cleanly at a full word boundary with ellipsis — never mid-sentence with awkward wrapping.
3. Make sure every card in a row has equal height regardless of description length.
4. Keep tag pills (e.g. "Next.js", "TypeScript") limited to 3 per card max — if a project has more, show the 3 most relevant plus a "+2" indicator, don't wrap to a second row.

---

## Phase 5 — Work History section

1. Redesign the timeline entry layout so year, role, company, and date range each have one clear position — no duplication.
2. Use consistent date format across all entries.
3. Confirm the connecting timeline line (if present) aligns precisely with each year marker at every breakpoint.

## Phase 6 — Contact section

1. Reduce the stat block to at most 2 numbers, and choose ones that reinforce credibility rather than undercut it. If "years of experience" is low, lead with project count and technology count instead, and either drop the years stat or reframe it (e.g. don't put "1+ Years Exp." at equal visual weight next to "20+ Projects").
2. Cut the redundancy in the closing messaging — you currently have three separate statements all saying "I'm available/let's work together" (headline, italic quote, "Currently Available" block). Keep ONE of these as the primary statement and either delete the others or fold them into a single supporting line.
3. Keep the contact form simple: Name, Email, Message — no extra fields.
